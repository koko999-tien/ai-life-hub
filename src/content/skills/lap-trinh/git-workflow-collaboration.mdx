          # 🌿 Git Workflow Đề Xuất: GitHub Flow (vì team 8 người, release weekly)

          ## 1. So sánh 3 model
          | Model | Ưu điểm | Nhược điểm | Phù hợp |
          |-------|---------|-----------|---------|
          | GitFlow | Nhiều release song song, rõ ràng | Phức tạp, merge nhiều | Enterprise, release chậm |
          | GitHub Flow | Đơn giản, CI/CD dễ | Không phù hợp nhiều release | Startup, release nhanh ✅ |
          | Trunk Based | Đơn giản nhất, merge conflict ít | Cần discipline cao | Team rất lớn, CI mạnh |

          ## 2. GitHub Flow chi tiết
          ```
          main (production-ready, protected)
            └── feature/abc-123 (mỗi ticket)
            └── feature/xyz-456
          ```

          **Naming convention:**
          - `feature/ABC-123-mo-ta-ngan` (feature mới)
          - `fix/ABC-456-sua-loi` (bug fix)
          - `hotfix/ABC-789-khan-cap` (production bug)
          - `chore/...` (cập nhật tool, config)

          ## 3. Quy trình PR
          1. Tạo branch từ `main`
          2. Code + commit nhỏ, có ý nghĩa
          3. Push branch, tạo Pull Request
          4. CI chạy tự động (test, lint, build)
          5. ≥ 1 reviewer approve
          6. Squash merge vào `main`
          7. Xóa branch

          ## 4. Giải quyết Conflict
          - **Ưu tiên:** Rebase feature branch lên `main` mới nhất trước khi merge
          - **Tránh:** Merge `main` vào feature nhiều lần (tạo commit rác)
          - **Tool:** Dùng VS Code merge editor hoặc `git mergetool`

          ## 5. Tags & Releases
          - Tag theo SemVer: `v1.2.3`
          - GitHub Release kèm changelog tự động (github-changelog-generator)
