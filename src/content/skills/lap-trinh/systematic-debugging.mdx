          # 🔍 Debug Plan: API 500 Intermittent Under Load

          ## Bước 1: Tái hiện (Reproduce)
          **Hypothesis:** Connection pool exhaustion / DB connection leak / Resource limit
          **Min Repro:**
          - Load test: `k6` hoặc `artillery` simulate 100 VUs, ramp up 5 phút
          - Theo dõi: DB connections count, Redis connections, Node.js event loop lag
          - Correlation: Map 500 errors với pool metrics

          ## Bước 2: Khoanh vùng (Isolate)
          **Binary Search Strategy:**
          1. Bypass Redis cache → test → nếu vẫn lỗi → không phải Redis
          2. Tăng DB connection pool limit → test → nếu hết lỗi → pool exhaustion
          3. Check Prisma connection lifecycle: `prisma.$connect()` / `$disconnect()` trong request handler?
          4. **Tools:**
             - `kubectl top pods` - CPU/Memory
             - `pg_stat_activity` - active connections
             - Node.js `--inspect` + Chrome DevTools heap snapshot
             - Datadog/New Relic APM trace

          ## Bước 3: Sửa triệt để (Root Cause Fix)
          **Likely Root Causes & Fixes:**
          | Nguyên nhân | Fix |
          |------------|-----|
          | Prisma không disconnect đúng (middleware) | Thêm `await prisma.$disconnect()` trong graceful shutdown |
          | Connection pool limit quá thấp (default 10) | Tăng `connection_limit=20` trong DATABASE_URL |
          | Không có retry logic cho transient DB errors | Thêm exponential backoff retry (p-retry) |
          | Kubernetes pod memory limit quá thấp → OOM kill | Tăng memory limit, thêm liveness probe |

          ## Bước 4: Test chống tái phát
          - **Unit test:** Mock Prisma, simulate connection error → expect retry
          - **Integration test:** Testcontainers PostgreSQL, load test 50 VUs
          - **Monitoring alert:**

          - **Chaos engineering:** Kill DB pod, verify graceful degradation
